# Contributing

Thanks for wanting to. A few things make it smooth.

1. **Read [docs/Architecture.md](docs/Architecture.md) first**, especially the warning about comments inside the long one-line statements.
2. **Play what you change.** `npm run check` only proves the files parse.
3. **Old saves must keep loading.** Give every new field a default.
4. **One change per pull request**, with a sentence on how you tested it.
5. **Keep the guide honest.** If behaviour changes, update `game/guide.js` and run `npm run guide`.
6. **Docs live in `docs/`.** The wiki is a mirror; do not edit it directly.

Big idea? Open an issue first so nobody builds the same thing twice. Questions are welcome on [Discord](https://discord.gg/8FcgxwJ3dM).
